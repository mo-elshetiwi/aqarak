# @aqarak/mobile

I implement the bilingual mobile shell for person accounts with manager, owner, tenant and technician capacities. I use shared colour and typography tokens, IBM Plex fonts, English and Arabic catalogues, and guarded role routes. I keep server authorisation separate from these navigation guards.

I run the development workspace with `pnpm --filter @aqarak/mobile dev`. I configure it through `.env.example`: `EXPO_PUBLIC_AUTH_ADAPTER` defaults to `fixture`, and `EXPO_PUBLIC_API_BASE_URL` is required for `http`. I accept HTTPS endpoints, with HTTP permitted only for localhost and the Android development host in development mode. I use synthetic demo accounts with any non-empty password in fixture mode. I show a Demo label and disclose those usernames on the sign-in screen.

I keep the access token only in a private memory ref. I persist the refresh token and active company through Expo SecureStore, and I retain the non-personal language preference on sign-out. I keep the splash visible until fonts, locale and session restore are ready. I renew sixty seconds before expiry and on foreground activation, share refresh work across concurrent requests, and retry an unauthorised request once. I emit `signed_out` and `context_changed` events for later cache and capture-file cleanup; future query keys start with `[accountId, companyId]`. I reject responses that arrive after an account or company boundary changes.

I expect `POST /v1/auth/sign-in`, `POST /v1/auth/refresh`, `POST /v1/auth/sign-out` and `GET /v1/me`. I validate the local contract in `src/features/auth/contract.ts` until a generated API client exists. I send username, password and `client: "mobile"` at sign-in, refresh credentials with `client: "mobile"` at renewal, and bearer authorisation on person and sign-out requests. I accept optional refresh rotation and RFC 9457 problem details with a `code` extension. I bound each auth request to fifteen seconds and expose only localisable error codes.

I run `pnpm --filter @aqarak/mobile typecheck`, `pnpm --filter @aqarak/mobile lint` and `pnpm --filter @aqarak/mobile test` for static checks and Jest tests in band. I test navigation and auth-state transitions with the real route files. I use `pnpm --filter @aqarak/mobile build` for an Android JavaScript export, which does not compile or install a native application.

I use the Expo Router `LocaleProvider` exported by the installed SDK, alongside native direction correction and a guarded reload when the direction changes. I preserve Western digits in both languages. I retain the specified light muted-text colour pair, whose contrast is 4.3977:1, as documented in the shared token tests.

I test the HTTP adapter against fake fetch responses, not a deployed API. I have not run the app on a physical phone; on the Android emulator I checked only the sign-in screen, in English and Arabic, from a debug development build. I do not provide biometric unlock. Arabic strings await review by me. The role screens describe their intended content without fabricated records or counts.

I use native reading-start alignment in both languages, apply the selected language to both native direction flags, and use the Arabic font family for Arabic navigation. I verify these choices with regression tests.

I preserve the shared overlay alpha in both schemes and resolve Tailwind colours through the public token package.

I classify authentication transport failures by HTTP status before reading the body, including bare unauthorised responses and HTML gateway failures. I reserve malformed-success errors for invalid successful responses.

I mark every demo context with the attention tone, including sign-in, account and role headers.

I keep one QueryClient per signed-in session and build every server key with `companyQueryKey` as `[accountId, companyId, ...parts]`. I expose `useCompanyQuery` with the authorised transport, pause queries offline, retain cached data in memory for up to thirty minutes after use, and retry only network or server failures at most twice. I clear the cache on sign-out and company switch. I do not persist query data to disk. I show the last successful fetch time in the offline banner and expose `useOnlineRequirement` for server decisions. I have not yet connected these primitives to API-backed screens.

I validate captured metadata with Zod and return typed results with bilingual refusals. I accept PDF, JPEG, PNG and HEIC documents up to 20 MB, checking lower-cased extensions against MIME types and verifying actual file sizes. I define audio limits of 25 MB and five minutes, and video limits of 100 MB and sixty seconds. I use binary megabytes consistently. I copy picked files into the app-private `Paths.cache/capture/` folder through the current file-system API, remove temporary picker copies, invalidate late results and drain pending copies before sign-out or company cleanup. I clear leftovers at startup. Capture is not yet connected to an upload endpoint or a screen.

I provide `CameraCapture` with photo and video modes, translated camera and microphone rationales, explicit permission continuation and a settings action after denial. I take photos with EXIF disabled, keep video audio enabled, and request a native sixty-second and 100 MB recording maximum. Video duration metadata is an elapsed-time estimate bounded by that native maximum. I stop recording when the app leaves the foreground or the capture view unmounts and discard late unclaimed results. I test camera and microphone permissions with mocks; a physical-device run is still required. The camera component is not yet connected to a capture sheet or upload endpoint.

I provide tap-to-start and tap-to-stop voice notes through expo-audio, with metering, Western-digit elapsed time, a five-minute native limit, playback, explicit discard and confirmation before leaving an unsaved recording. I validate the 25 MB and five-minute limits before retaining recordings in the same private capture folder, and I wipe them on sign-out and company switch. I request microphone permission only after the translated rationale is continued. I test audio and permission behaviour with native mocks; I still need a device run. Capture is not yet connected to an upload endpoint.

I provide status tags for drafted actions, approvals and contracts, with words and tone-specific icons. I use Lucide Contrast for the progress half-circle. I format integer fils with integer arithmetic, show Gregorian Dubai dates and Western digits, and isolate mono identifiers left to right while preserving separators in list masks. I provide Empty, Loading, Error, Not found, Expired draft and Pending approval states alongside the existing Offline banner. I keep skeletons static under reduced motion and reuse the honest role-tab sentences in Empty states. I accept a caller-supplied frozen stepper in Pending approval; these components are not yet wired to API data.

I provide a schema-validated drafted-action confirmation card with bilingual origins, plain-text before and after values, expiry and consequence copy. I prevent repeated decisions while work is pending and after a successful confirmation, expose offline blocking reasons, and route approval kinds to review. I keep these callbacks independent of fetching; API integration remains outstanding.

I provide a frozen owner-gate approval stepper and scrolling owner and tenant reviews with parsed props, version changes, exact rent, lock notices and role-specific consequences. I require a second confirmation before approval and a trimmed 1 to 500 character reason for changes, with identical summary and field errors. I serialize callbacks and disable server decisions when blocked. I use flexible-height controls for enlarged text; physical-device accessibility and API integration remain unverified.

I expose a signed-in development-only gallery at `/gallery`, linked from the person account screen. I label its fixed contract, people and review examples as synthetic data. I provide a bottom capture sheet for photo, video, voice note and PDF or image documents, with type and quality guidance, private item metadata and removal. I show all screen states, status maps, drafted-action states, owner and tenant reviews and the stepper without an owner gate. I keep gallery actions local; capture has no upload endpoint, components have no API data, and camera and microphone validation still uses mocks until a device run.
